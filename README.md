# Job Application Orchestrator

Локальное веб-приложение для поиска работы: для каждой сессии оно использует выбранное резюме с той же площадки, где выполняется поиск, ищет вакансии в видимом Chromium и передаёт данные OpenAI-compatible модели. Разрешённые модельные операции получают полный нормализованный снимок резюме, включая личные данные и контакты; подробности хранения и ограничения передачи приведены ниже.

Приложение не использует скрытые API сайтов. Сайты открываются через Playwright в локальном профиле браузера; authentication state Chromium остаётся только в игнорируемом `data/browser-profiles`. После явного подтверждения ссылка и нормализованные данные HH.ru, HireHi или Zarplata.ru сохраняются в защищённой локальной копии источника для последующих сессий; каждая сессия получает собственный неизменяемый снимок. В БД и снимках не копируются cookies или browser storage, а сырые HTML/PDF/DOCX/TXT не сохраняются. Настройки и SQLite-база хранятся локально в `data/`.

## Что умеет

- добавлять, обновлять и удалять сохранённые ссылки на резюме в Профиле, а также показывать сводку полученных данных;
- использовать одно явно подтверждённое резюме на сессию с HH.ru, HireHi или Zarplata.ru;
- автоматически обрабатывать короткие обязательные вопросы вакансий на основе подтверждённых данных;
- искать и оценивать вакансии по задачам, навыкам, опыту, роли, сфере и особым требованиям;
- показывать разбор оценки и генерировать сопроводительное письмо на основе снимка текущей сессии;
- вести параллельные сессии на разных площадках, с лимитами, событиями и уведомлениями.

### Площадки и сценарии

**HH.ru** — поиск, оценка и отправка откликов по заданным правилам и лимитам сессии. Анкеты и короткие тесты обрабатываются автоматически: текстовые и числовые поля, выбор одного или нескольких вариантов. Личные ответы строятся из профессиональных данных снимка текущей сессии и подтверждённых данных источника; короткие вопросы на знания и логику решает модель при высокой уверенности. `AuthenticationPending` сохраняет сессию в состоянии **В работе** и автоматически перепроверяется; CAPTCHA переводит сессию на паузу до действия пользователя в открытом браузере. Неизвестный вопрос вакансии не ставит сессию на паузу: система пытается ответить автоматически, а если безопасный ответ невозможен, фиксирует ошибку вакансии и продолжает обработку остальных. Чувствительные, тестовые, небезопасные и неразрешимые вопросы не сохраняются и не отправляются автоматически.

- Красные флаги проверяются по полному ответу модели: для каждого заданного флага должны быть явно указаны совпадение, уверенность, подтверждающая цитата и объяснение. Неполный ответ запрашивается повторно; неподтверждённый результат не разрешает отклик и помечает вакансию ошибкой обработки. Подтверждённое совпадение отбраковывает вакансию.
- Явно обязательные требования к целевой роли, среде и задачам проверяются отдельно от положительных пожеланий. Их основание должно подтверждаться точной цитатой из пользовательского описания, а совпадение — цитатой из полей вакансии, включая работодателя. Если первичная оценка подтверждает все обязательные условия, отдельная проверка получает только вакансию и эти условия, без резюме и первичного решения. Она должна подтвердить всю комбинацию условий с уверенностью не ниже 0,90 и точными цитатами; частичное совпадение исключает отклик. Необязательные пожелания влияют на оценку. Неизвестную зарплату или оформление нельзя приравнивать к подтверждённому нарушению. Сохранённые предпочтения прежнего формата компилируются заново из исходного описания.
- Подтверждённое пожелание по сфере, в том числе разрешение новой отрасли, имеет приоритет над отраслевым опытом резюме: для текущего формата предпочтений нужна уверенность не ниже 0,70 и точная цитата вакансии. Тогда критерий сферы получает максимальную оценку; проверки задач, навыков, обязательных условий и запретов продолжают действовать. Смена контракта оценки исключает повторное использование несовместимых сохранённых решений.

Перед использованием сопроводительного письма отдельная модельная проверка сопоставляет фактические утверждения о кандидате с профессиональными данными выбранного резюме. Требования работодателя не служат доказательством навыков кандидата. Код проверяет цитаты и их источники; смысловое соответствие остаётся оценкой модели. Неподтверждённый текст переписывается с ограниченным числом попыток либо завершается ошибкой вакансии. Сохранённые письма проверяются до отправки или включения в отчёт; подтверждение привязано к точному тексту, снимку резюме и версии проверки.

### Дополнительные формы HH.ru и зарплата

- Зарплата берётся из снимка резюме текущей сессии, если в описании желаемой вакансии нет зарплатных условий.
- Зарплатные условия из описания желаемой вакансии имеют приоритет над резюме. Используется исходный текст описания, включая сложные условия, а не общий минимум из поисковых предпочтений.
- Раздел «При заполнении вопросов о ЗП указывай:» задаёт суммы для анкеты отдельно от предшествующих порогов отсева вакансий. Общий порог из остального описания не подставляется, если ни одно правило раздела не подошло.
- Например, «офис МСК — 250 тыс. RUB на руки, удалённо — 180 тыс. RUB на руки» задаёт разные суммы для офиса в Москве и удалённой работы. Система проверяет город, формат работы и остальные условия конкретной вакансии. Если условия не совпали, противоречат друг другу или не хватает данных, точное правило не применяется: система формирует отдельную оценку по исходным правилам, снимку резюме текущей сессии и вакансии.
- Диапазон опыта HH «1–3 года» и «3–6 лет» сопоставляется с пользовательскими границами; пересечение правил на ровно 3 годе остаётся неоднозначным и переходит в оценку.
- Валюта, период и указание «до налогов» / «на руки» сохраняются. Автоматического пересчёта валют или налогов нет: оценка должна сразу соответствовать требованиям поля и подтверждённым исходным ориентирам.
- Точное зарплатное правило применяется только при полном совпадении условий и уверенности модели 100%. При неполном или пересекающемся совпадении система запрашивает отдельную обоснованную оценку по исходным правилам, снимку резюме текущей сессии и вакансии; это не зависит от «Гарантированного отклика».
- Если вопрос требует сумму после налогов или до налогов, оценка формируется сразу в этой базе. Код не выполняет неподтверждённый пересчёт net/gross; при отсутствии исходных зарплатных ориентиров вакансия получает ошибку обработки.
- Для подходящей вакансии плашка «Вы откликаетесь на вакансию в другой стране» подтверждается автоматически. Это подтверждение продолжения отклика, а не заявление о готовности кандидата к переезду.
- Ответы сохраняются в локальном плане до заполнения, привязываются к вопросу и вариантам и проверяются после ввода. Поддерживается до пяти шагов формы, включая поля, появляющиеся после выбора ответа. Та же форма после отправки не отправляется повторно автоматически; успех засчитывается только по подтверждению HH.ru.
- При отклике в один клик HH и Zarplata могут сначала принять выбранное резюме. Подготовленное сопроводительное отправляется отдельным действием: через форму HH либо поле с кнопкой письма на Zarplata. Подтверждение резюме само по себе не подтверждает письмо. Во время отправки письма программа ждёт до 30 секунд; неподтверждённый результат не считается успехом и не приводит к повторному нажатию.
- Если нужны только заданные суммы без оценки, добавьте в описание: «Зарплата: только точные правила; без оценки.» В этом режиме отсутствие подтверждённого города, формата, опыта или налоговой базы оставляет зарплатный вопрос без ответа. Обязательный неразрешимый вопрос завершает обработку вакансии с ошибкой; остальные вакансии продолжаются. Полное описание может уточнить диапазон опыта карточки; ровно 3 года относится к группе ≤3, а диапазон 3–6 без уточнения остаётся неоднозначным.
- Новая сессия может заново оценить прежние технические ошибки и отклонённые вакансии. Повторное использование анализа требует совпадения резюме, критериев и контрактов. Подтверждённые отправки защищены общей историей; частичные и неопределённые результаты сначала сверяются с сайтом.
- Принятое резюме с незавершённым письмом отображается отдельно: «Резюме отправлено, письмо не завершено» (`PARTIAL`). Этот исход учитывается в лимите внешних откликов, но не в счётчике полного успеха. Сохранённое письмо продолжается после сверки без повторной отправки резюме, с пределом трёх попыток. При несовместимом снимке или плане автоматическое продолжение блокируется, а частичный результат сохраняется. Если заданы обязательные условия поиска, устаревшая или отсутствующая оценка пересчитывается до продолжения письма; неподтверждённое соответствие блокирует письмо и сохраняет принятый CV. На HH и Zarplata намерение отправить письмо сохраняется до действия; если после него результат неизвестен, повторная отправка блокируется до независимого подтверждения.

**HireHi** — только сбор подходящих вакансий и PDF-отчёт. Формы не заполняются, отклики не отправляются, отдельный список контактов не ведётся. В отчёт попадают ссылка, маршрут вакансии и найденные контакты, чтобы пользователь сам решил, что делать дальше.

**Zarplata.ru** — поддерживает импорт публичной HTML-ссылки и работу с вакансиями площадки. Отклик может открыться отдельной страницей формы: она принимается только на разрешённом HTTPS-домене и при точном совпадении ID вакансии. Текстовые вопросы работодателя на такой странице распознаются отдельно от сопроводительного письма. Структура резюме извлекается отдельным адаптером Zarplata.ru; локаторы HH.ru и HireHi не переиспользуются.

Поддерживаются только прямые HTTPS-ссылки вида `https://hh.ru/resume/<id>` (включая разрешённый региональный поддомен HH.ru), `https://hirehi.ru/resume/<id>` и `https://zarplata.ru/resume/<id>` (включая разрешённые поддомены). До открытия проверяются выбранный адаптер, схема, hostname, отсутствие учётных данных и произвольного порта, путь и идентификатор. Редирект после открытия проверяется тем же адаптером; PDF/ATS-ссылка не заменяет HTML-страницу.

## Резюме и приватность

На вкладке **Профиль** для каждой площадки показаны её название, ссылка на резюме и сводка полученных данных. Наличие раздела или контакта отмечено зелёной галочкой, отсутствие — красным крестиком. Для нового источника вставьте URL и нажмите основную кнопку на всю ширину **Сохранить ссылку**; пока поле пустое, кнопка отключена. После сохранения поле становится доступным только для чтения, а основная кнопка **Обновить данные** повторно читает сохранённую ссылку. Под ней расположены две одинаковые кнопки с иконками. Карандаш включает редактирование: **Сохранить изменения** запускает замену источника, а крестик отменяет её и возвращает сохранённый URL. Корзина открывает диалог с вопросом об удалении, в котором показаны URL резюме и площадка; удалить его можно кнопкой **Да**, а **Нет** отменяет действие.

Технические данные снимка резюме, его полноты и контекста ИИ в карточках сессий не показываются.

Изменения URL, потеря фокуса и нажатие Enter сами по себе не обращаются к серверу. Импорт или замена начинается только по нажатию основной кнопки. Интерфейс выполняет предпросмотр ссылки, затем сохраняет источник с согласием `consent=true`; если backend запросит род для сопроводительных писем и сохранённого предпочтения ещё нет, сначала показывается вопрос. Род не выводится из имени. **Обновить данные** вызывает обновление сохранённой копии, а **Да** в диалоге удаления — удаление.

Уже сохранённые и пригодные копии резюме продолжают поддерживаться: сессии используют их без сетевой проверки источника и без preview token. При успешном обновлении фиксируется новая локальная копия; неудачное обновление оставляет последнюю исправную копию доступной. Если сохранённый источник отсутствует или локальная копия повреждена либо не содержит обязательных данных, backend блокирует запуск сессии; форму сессии можно настроить только после сохранения пригодного источника в Профиле. Восстановление принятой сессии использует её неизменяемый снимок и `content_hash`, не перечитывая источник.

Статус заполненности строится по проверенной полной локальной копии, а не по краткому preview: «Не заполнено», «Заполнено», «Частично» или «Ошибка». Полными считаются основные разделы: личные данные, контакты, цель, местоположение, опыт, навыки, образование, языки, обо мне и общий стаж; портфолио и дополнительные разделы на этот статус не влияют. Новую сессию можно запустить только с пригодной копией со статусом «Заполнено» или «Частично».

Backend lifecycle источников не меняется. Импорт и замена используют `POST /api/resume-sources/preview` и `POST /api/resume-sources/confirm`; сохранение `consent=true` запускается явным нажатием основной кнопки. `GET /api/resume-sources` загружает сохранённые источники, `POST /api/resume-sources/{adapter_id}/refresh` обновляет копию, а `DELETE /api/resume-sources/{adapter_id}` удаляет её после подтверждения. `PATCH /api/resume-sources/{adapter_id}` остаётся доступен через API для изменения ранее сохранённого предпочтения рода; отдельного редактора этого предпочтения в Профиле нет. Если сайт не предоставил допустимый род, пользователь задаёт его для источника; значения пола «Мужчина» и «Женщина» в HH.ru и Zarplata.ru нормализуются в `male` и `female`, род не выводится из имени. Для первого сохранения и явного обновления ссылка должна быть доступна сайту. Публичная ссылка может выступать bearer-идентификатором, поэтому не делитесь ею; токен предпросмотра короткоживущий и используется для подтверждения. Для всех трёх площадок нормализованный snapshot с identity и contacts хранится в защищённой локальной копии; `private_view` остаётся sealed для локального рендеринга и legacy fallback, а публичный preview не раскрывает identity/contacts. `start`, `resume` и `stop` источник не перечитывают. Каждая сессия использует собственный неизменяемый `content_hash`.
Модель получает содержимое полей резюме без служебных обёрток. `coverage`, `availability`, `source_section` и `source_locator` остаются в локальном снимке и не передаются модели.
Модель оценки, планировщик поиска и другие model consumers получают разрешённый полный нормализованный snapshot, включая identity и contacts; технические metadata, bearer identifiers, locators, tokens и raw markup остаются за границей allowlist. При подготовке сопроводительного письма writer сохраняет названия профессиональных навыков, но скрывает прямые идентификаторы и свободный текст контактов; локальный рендеринг подставляет разрешённые данные из sealed `private_view` по выбранной политике, подписывая URL мессенджеров и социальных сетей и выводя каждый адрес с новой строки. Текст резюме и вакансии считаются недоверенными данными и проходят prompt-injection boundary.

## Быстрый запуск на Windows

Нужны Windows 10/11 и доступ к интернету. Git требуется только для клонирования и обновления исходников. Единый скрипт при необходимости подготовит WinGet, сам установит Python 3.12 и Node.js LTS, создаст окружение, установит зависимости, соберёт интерфейс и запустит приложение:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Откроется <http://127.0.0.1:8000>. Окно PowerShell остаётся открытым, вывод Uvicorn виден в консоли, а `Ctrl+C` завершает приложение и освобождает порт. Повторный запуск безопасно перезапускает принадлежащую этому проекту копию, пропускает уже выполненные установки и пересобирает frontend только после изменения исходных файлов. Миграции базы применяются при каждом запуске. Доступны параметры `-Port 8100`, `-NoBrowser`, `-ForceSetup`, `-ForceRebuild` и `-Stop`. Чужой процесс на выбранном порту скрипт не останавливает.

Для разработки с hot reload по-прежнему можно запустить:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1
```

В dev-режиме интерфейс доступен на <http://127.0.0.1:5173>, API — на порту 8000. Основной `run.ps1` создаёт `.venv`, устанавливает зависимости и Chromium Playwright, собирает frontend и применяет миграции SQLite. Порт основного запуска можно изменить: `powershell -ExecutionPolicy Bypass -File .\run.ps1 -Port 8100`.

Файл `.env` для запуска не нужен и создавать его не следует. Приложение стартует со встроенными безопасными значениями, а Base URL, API-ключ и имя модели задаются и сохраняются в разделе **Модель**. Переменная `JAO_DATABASE_URL` поддерживается только как явный одноразовый override для запуска миграций (например, изолированной тестовой базы); она не заменяет настройки модели и не требует `.env`.

Локальный шлюз, например Antigravity Tools, можно настроить в разделе **Модель** сразу после установки: укажите его Base URL (`http://127.0.0.1:<порт>/v1` или `http://localhost:<порт>/v1`) и API-ключ, если шлюз требует авторизацию. `http://0.0.0.0:<порт>/v1` автоматически заменяется на `http://127.0.0.1:<порт>/v1`. Локальные запросы не используют системный HTTP-прокси. Затем загрузите список моделей или введите точное имя вручную и сохраните выбор. Сохранение выполняет короткий запрос `POST /chat/completions` с проверкой JSON-ответа; это может расходовать токены. Настройки сохраняются только после успешного ответа. Используйте адрес и порт из настроек шлюза; `http://127.0.0.1/v1` без порта означает порт 80. При переносе настроек на другой компьютер сохранённый ключ Windows DPAPI может быть недоступен — введите ключ заново через интерфейс.

## Первый запуск и повседневный поток

1. Откройте вкладку **Модель**, укажите HTTPS Base URL облачного OpenAI-compatible API, API-ключ и модель. Ключ шифруется Windows DPAPI и не возвращается через API или логи.
2. Откройте **Профиль**, вставьте ссылку на резюме нужной площадки и нажмите **Сохранить ссылку**. Если сервис запросит род для сопроводительных писем, укажите его в появившемся вопросе. Для замены сохранённого URL нажмите карандаш, вставьте новый адрес и выберите **Сохранить изменения**; отмена крестиком вернёт прежний адрес. Для обновления или удаления используйте соответствующие кнопки и подтвердите удаление в диалоге. Сессия запускается с пригодной локальной копией сохранённого источника.
3. В **Сессии** выберите площадку, для которой уже есть пригодный сохранённый источник, задайте лимиты и коротко опишите желаемую вакансию. Резюме должно быть с того же сайта, где выполняется поиск. Сопроводительное письмо можно поручить модели автоматически или снять этот флажок и ввести собственную структуру. В шаблоне поддерживаются безопасные placeholders `{{full_name}}`, `{{phone}}`, `{{email}}` и `{{messengers}}`; они заменяются локальными данными снимка перед показом или отправкой. Произвольные квадратные скобки не являются способом передачи данных и удаляются/отклоняются проверкой. При ручной структуре перед запуском нужен непустой текст.

4. Chromium открывается автоматически с сохранённым профилем сайта. При первом входе авторизуйтесь в нём; программа заметит вход автоматически. Если появится CAPTCHA, в том числе модальное окно поверх страницы вакансии, сессия приостановится, а браузер останется открытым. Решите проверку в браузере, затем нажмите **Продолжить**.
5. В **Вакансиях** просмотрите оценки, объяснения и сопроводительные письма. Для HireHi скачайте PDF-отчёт; ход HH.ru-сессии контролируйте по статусам и событиям.

Форма новой сессии автоматически сохраняется в браузере и в локальной базе приложения (`session_form_draft`). Описание, сайт, лимит, влияние факторов и настройки сопроводительного письма восстанавливаются при смене браузера или адреса приложения, если используется та же база. Статус под описанием подтверждает сохранение на компьютере; при недоступности сервера повторная попытка выполняется автоматически. Изменения из старой вкладки не перезаписывают более новую копию: интерфейс предложит явно загрузить её. При первом открытии после обновления описание можно восстановить из последнего запуска с непустым описанием; намеренно очищенное и сохранённое поле остаётся пустым.

## Автоматическое восстановление сессий

Принятые к запуску сессии HH.ru и Zarplata.ru продолжают адаптивный поиск до лимита внешних откликов либо явной остановки пользователя. Общий планировщик использует доступные видимые источники и обратную связь по релевантности и новым ID; сайт определяет доступность рекомендаций и связанных страниц. После обхода источников выполняется ограниченная пауза и новый проход. Абсолютная полнота выдачи не гарантируется. HireHi adaptive продолжает поиск до явной остановки пользователя, кроме human blocker или fatal safety ошибки. Восстановление использует тот же временный снимок резюме и его `content_hash`, а не перечитывает изменившийся источник посреди сессии.

- Временные ошибки модели повторяются с сохраняемым бюджетом до четырёх вызовов логической операции, включая восстановление процесса. Таймаут запускает настоящий новый запрос; исчерпанный бюджет и постоянные ошибки не изображают повторное выполнение. Очередь ограничена десятью незавершёнными запросами на сессию и тридцатью всего; исполнение начинается со своим бюджетом 180 секунд, включая исправление JSON. Ожидание слота имеет отдельный конечный бюджет 6600 секунд и различимую ошибку перегрузки.
- Проверка модели и подготовка предпочтений выполняются внутри восстанавливаемой задачи: временная недоступность API больше не блокирует принятие запуска.
- План поиска, позиция в выдаче HH, незавершённая очередь, оценки, письма и счётчики сохраняются. Ошибка чтения отдельной вакансии не мешает обработать остальные; непрочитанная вакансия возвращается в следующую попытку, даже если исчезла из выдачи. Если описание пустое или не удалось прочитать его после трёх попыток, вакансия получает понятную ошибку и обработка продолжается со следующей. Наличие ошибок чтения не считается исчерпанием выдачи.
- HireHi сохраняет выбранную категорию и повторяющиеся фильтры грейда при переходах. Позиция выдачи и найденные ID сохраняются вместе с очередью: после сбоя поиск продолжается с незавершённой страницы. Повторная выдача без новых вакансий завершает обход; ссылки на статьи не считаются вакансиями.
- Закрывшийся браузер открывается с тем же локальным профилем. После перезапуска backend активные сессии продолжаются автоматически. Черновики, остановленные и завершённые сессии не запускаются заново; пауза CAPTCHA сохраняется.
- Перед действием, способным отправить отклик (в том числе открытием формы HH с отправкой в один клик), сохраняется состояние отправки. После сбоя программа сначала проверяет результат на сайте. Повтор допускается только при явном предложении нового отклика на загруженной странице авторизованного пользователя. Неподтверждённые неоднозначные результаты не засчитываются в цель и не отправляются повторно вслепую; программа переходит к другим вакансиям.
- Подтверждение отклика HH или Zarplata после CAPTCHA либо перезапуска подтверждает только резюме. Если план предусматривает письмо, полный успех требует отдельного подтверждения письма. Продолжение ещё не отправленного письма разрешено после сверки при видимом действии прикрепления, диалоге или отдельном поле с кнопкой письма. Неопределённый результат уже начатой отправки письма, отсутствующий либо несовместимый план блокируют автоматическое продолжение этой вакансии; частичный исход сохраняется, остальные вакансии обрабатываются дальше.
- В поиске HH нет общего ограничения в 100 страниц; рекомендации обходятся постранично, если сайт открыл для них поисковую выдачу. При отсутствии дополнительных запросов используется общая выдача. Пустая или повторяющаяся страница завершает только текущий источник или проход. HH сохраняет точные ID и курсоры, затем обновляет источники с ограниченной паузой, даже если в сессии пока не оценено ни одной вакансии.

Восстановление не может гарантировать доступность стороннего сайта или модели. Для работы нужны настроенная модель, подтверждённый снимок резюме нужной площадки и действующая авторизация. Если сайт действительно завершил авторизацию, войти нужно в открытом браузере; проверка входа выполняется автоматически, без ручного перезапуска сессии. В обычном режиме обязательные вопросы работодателя программа заполняет только подтверждёнными сведениями. Если безопасный ответ на неизвестный вопрос невозможен, вакансия получает ошибку с кодом и понятным описанием, а обработка остальных продолжается.

Неизвестный вопрос анкеты не ставит сессию на паузу и не появляется как ручная анкета в карточке сессии: система пытается ответить автоматически. Если безопасный ответ невозможен, для вакансии показывается безопасная ошибка с кодом и понятным описанием, а остальные вакансии продолжают обрабатываться. Пароли и коды доступа не сохраняются. HireHi по-прежнему формирует отчёт без отправки откликов.

При запуске можно включить «Гарантированный отклик» (по умолчанию выключен). В этом режиме модель может дополнить отсутствующие сведения правдоподобными предположениями. Они отмечаются как `assumption` в плане отклика и не становятся подтверждённым ответом. Режим не гарантирует отправку или оффер; правила зарплаты, чувствительных вопросов и согласий продолжают действовать. Актуальное описание зарплатных ожиданий имеет приоритет над резюме; ответ этой сессии используется только при отсутствии ожиданий в обоих источниках.

Скрипты `run.ps1` и `start-dev.ps1` применяют миграции перед запуском, включая `0022` с состоянием восстановления. При прямом запуске Uvicorn сначала выполните `.venv\Scripts\python -m alembic upgrade head`. Обновление проверяется на отдельной пустой базе, рабочие данные для тестов не используются.

Адаптер HH считывает видимый блок зарплаты: границы суммы, валюту и указание «на руки»/«до вычета налогов». Исходные условия оплаты также сохраняются в описании и передаются модели, включая период оплаты. Почасовые, посменные и годовые суммы не выдаются за месячную зарплату. Исправление применяется при новом чтении вакансии; ранее сохранённые оценки автоматически не пересчитываются.

## Ограничения и безопасность

- Полный разрешённый снимок резюме, включая контакты, может иметь дополнительные локальные копии в сохранённых входах модельных запросов и кэше. Каждые десять минут приложение ограниченно очищает payload запросов и кэш завершённых сессий старше 30 дней (до 100 записей каждого вида за проход). Активные, восстанавливаемые, частичные и неопределённые отправки защищены; история подтверждённых действий и технические metadata сохраняются. Эта политика не удаляет сам сохранённый источник резюме и не меняет согласованную передачу модели.
- История API загружается страницами: `GET /api/sessions/{id}/events?after=0&limit=500`, максимум 1000 событий. Следующий `after` — последний полученный ID. WebSocket принимает `?after=<последний ID>` при переподключении и передаёт историю порциями до 500 событий.

- Контур защиты ИИ от промпт-инъекций, результаты аудита и ограничения описаны в [SECURITY_AI.md](SECURITY_AI.md). Управляющие фразы инъекции исключаются из данных для ИИ; небезопасная вакансия останавливается с ошибкой `SECURITY_BLOCKED`, без ручной проверки.
- Публичный Base URL должен быть HTTPS; HTTP допускается для локального loopback-gateway, в том числе при первой настройке.
- Production использует облачный или локальный OpenAI-compatible API; mock-провайдер предназначен для тестов и демонстрации.
- Полный нормализованный снимок сессии, включая `identity` и `contacts`, передаётся только разрешённым модельным операциям по allowlist-контракту. `private_view` остаётся зашифрованным для локального рендеринга и совместимости со старыми снимками; публичный preview не раскрывает содержимое `identity` и `contacts`. Модель не должна придумывать опыт, контакты, даты или достижения.
- Не добавляйте в репозиторий `.env`, ключи, резюме, cookies, browser profiles, базу и отчёты: рабочие данные находятся в `data/`.

# Сравнение алгоритмов поиска

В `main` действует `baseline_v1`, в `develop` — `adaptive_v1`. Перед сменой ветки
остановите текущую сессию и сервер, затем запустите сервер заново и создайте новую
сессию. Обе ветки используют одинаковую схему БД и механизм измерений.

Адаптивный поиск HH ведёт независимый сохраняемый курсор каждого источника:
главные рекомендации, рекомендации из видимых страниц резюме, запросы по названию
и описанию, похожие вакансии, работодатели и широкий поиск без ключевого слова.
Для широкого поиска добавляются сегменты по региону/роли/отрасли, когда HH
показывает соответствующие ссылки фильтров. Формы и скрытые API не используются.
Страницы работодателей дают видимые вакансии и ссылки на полную выдачу, если они есть.

В цикле из десяти страниц шесть очередей предпочитают рекомендации, две —
продуктивный поиск, две — самый давно обслуженный поисковый источник. Свободные
очереди перераспределяются. Оценка учитывает новизну ID, долю подходящих вакансий,
стоимость обработки, давность наблюдений и разнообразие семейств ролей. Выбор
очередной страницы выполняется локально, без модельного вызова. Низкая отдача
не означает исчерпания; ошибка страницы откладывает её, сохраняя курсор.

Начальный план включает основные должности, синонимы, задачи/навыки и смежные роли.
После каждых 50 обработанных вакансий с подходящими примерами возможен новый
модельный раунд до 12 запросов; общего лимита в 12 запросов больше нет.
Завершённые рекомендации перечитываются после 20 новых обработанных вакансий;
при отсутствии новых ID интервал увеличивается до 320. Статичная выдача не
перечитывается бесконечно. Похожие названия не являются основанием для удаления:
точная дедупликация выполняется по ID. Исторические ID по-прежнему пропускаются,
сохраняя защиту от повторных откликов; изменения текста под старым ID автоматически
не переоцениваются. Это ограничение учитывайте при сравнении пересечений.

Исчерпание текущих источников запускает обновление поиска с ограниченной паузой и не
завершает сессию HH; закончить её можно лимитом подтверждённых откликов или кнопкой остановки.
Это не доказывает, что просмотрен весь HH. Доступность ссылок рекомендаций и фильтров
зависит от реального интерфейса аккаунта. Эффективность весов и долей очередей
проверяется экспериментом, а не считается заранее доказанной.

Каждая новая сессия автоматически сохраняет версию алгоритма, git-коммит, хеш
критериев и подтверждённого session resume snapshot, модель, лимит откликов, найденные ID, результаты
оценок и длительности операций. При завершении или остановке сохраняется итоговый
снимок. `GET /api/sessions/{id}/metrics` возвращает снимок или текущую статистику.
Экспорт нескольких запусков: `.venv/Scripts/python -m backend.services.compare_search 12 13`.
Сохраняйте выгрузки только в игнорируемом `data/`, не в git.

Основные показатели: число релевантных R, R / число уникальных найденных N,
R/час, время до 20/50/100 релевантных вакансий. Отдельно показаны оценённые,
неоценённые, пересечения с историей, дубли, источники, ошибки, модельные вызовы,
токены (если провайдер их возвращает) и отправленные отклики. Сводка модели
разделяет время очереди и provider, а также считает восстановления и исправления
ответов по безопасным категориям; служебные ID и ID вакансий в агрегат не входят.
Релевантность —
решение действующего оценщика до отправки отклика, а не независимая экспертная оценка.

Для эксперимента создавайте новые сессии с одинаковым источником/снимком резюме, критериями и моделью,
останавливайте после одинакового времени; лимит откликов влияет на сравнимость.
Чередуйте порядок develop/main и main/develop: HH меняет рекомендации после
просмотров и откликов, а общая история исключает ранее обработанные вакансии.
Неочищенная история сохраняет защиту от повторной отправки. Пересечения и
неоценённые вакансии не считаются отрицательными оценками. Старые сессии без
measurement_identity не подходят для количественного сравнения найденных вакансий.

### HireHi adaptive V1-V3

HireHi adaptive search is recorded by append-only `BrowserEvent` rows. The
report exposes `D` (unique discovered vacancy IDs), `N` (unique vacancy IDs
with a first complete evaluation), `R` (relevant evaluations), `R/N`, `N/D`, `R@50/100/200`, exploration and
exploitation, source-level novelty, and audit false-negative rate. Supported
event types are `metric_discovery`, `metric_evaluation`,
`metric_hirehi_snapshot`, `metric_semantic_reuse`, and `metric_audit`.

The session checkbox `У меня есть подписка PRO` only enables already-available
PRO discovery tools; the application never buys a subscription. HireHi runs
until the user presses Stop (there is no automatic application limit).

Rollout requires at least 10 paired baseline/adaptive sessions with the same
criteria hash and model: audit FNR <=5%, median and aggregate early `R@100`
lift >=10%, and matched-checkpoint final `R` no worse than baseline by 5%.
Fewer pairs produce `insufficient_evidence`. Keep the rollback switch in
`JAO_HIREHI_SEARCH_VERSION` (`hirehi_v1` versus `hirehi_adaptive_v3`); assessment
does not change this flag automatically.

### Совместимость API моделей

Используются Base URL сервиса (включая путь, обычно `/v1`), его API-ключ в заголовке `Authorization: Bearer …` и точное имя модели. Префикс ключа не ограничен; ключ одного сервиса не подходит автоматически для другого. При смене Base URL сохранённый ключ не пересылается новому адресу. Для удалённого сервиса ключ обязателен, для локального — необязателен. Перенаправления отключены.

Нужен OpenAI-compatible Chat Completions endpoint; наличие `/models` само по себе не доказывает работоспособность генерации. При явном отказе сервера от `json_schema` применяется `json_object`, затем JSON по инструкции, всегда с локальной Pydantic-проверкой. Явно неподдерживаемые `temperature` и `max_tokens` согласуются повторным запросом. Ошибки авторизации и лимитов не вызывают переключение формата. Статус страницы проверяет только каталог без расхода токенов; для повторной проверки ответа сохраните настройки. Сервисы только с Responses API или собственным протоколом требуют отдельной интеграции.
