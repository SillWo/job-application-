# Job Application Orchestrator

Локальное приложение для анализа вакансий и безопасного управления откликами через видимый Chromium. Сайты управляются только через пользовательский интерфейс Playwright; API платформ не используются.

## Быстрый запуск (Windows)

Требуются Python 3.11/3.12, Node.js 20+ и Git. Для production требуется облачный OpenAI-compatible API; mock provider доступен только для демонстрации и тестов.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Откройте <http://127.0.0.1:8000>. Для разработки используйте `scripts/start-dev.ps1` (UI на `http://127.0.0.1:5173`). Linux-эквиваленты находятся в `scripts/*.sh`.

## Профиль и резюме

Профиль пользователя и резюме — разные сущности.

Личный профиль заполняется пользователем вручную и содержит:

- ФИО, место проживания и города/страны поиска работы;
- телефон, электронную почту и мессенджеры;
- образование с типом, учебным заведением, факультетом, специальностью, степенью и периодом обучения;
- языки и уровень владения;
- наличие водительских прав.

У пользователя может быть несколько отдельных резюме. Каждое резюме содержит предполагаемую должность, желаемый доход, тип занятости, формат работы, возможность командировок, все места работы с обязанностями, список навыков и раздел «О себе».

Пользователь самостоятельно выбирает, какие резюме имеют `selected_for_matching=true`. Только выбранные резюме используются при поиске и оценке вакансий. Для HH.ru используется должность из первого выбранного резюме; для HireHi дополнительно формируется набор широких запросов по смежным названиям должности.

## Импорт резюме

Резюме можно создать вручную или импортировать из PDF, DOCX и TXT. Импорт извлекает текст и заполняет структурированные поля личного профиля и отдельного резюме. После импорта пользователь обязан проверить результат и при необходимости отредактировать поля: модель может неверно определить границы разделов, даты, перечисления или значения перечисляемых полей.

OCR для PDF, состоящих только из изображений, в MVP не поддерживается. PDF должен содержать текстовый слой; для сканированных документов требуется предварительно выполнить OCR внешним инструментом либо заполнить профиль и резюме вручную.

## Оценка вакансий и сопроводительное письмо

При оценке вакансии в облачный OpenAI-compatible API передаются полный личный профиль и полный массив всех выбранных резюме. Передача отдельных facts, verified facts или отдельного слоя верификаций не используется.

При генерации сопроводительного письма передаются те же полный профиль и выбранные резюме. Модель должна использовать только эти данные и не придумывать опыт, контакты, навыки, даты, цифры или достижения.

Оценка вакансии проходит по следующей схеме:

- **Название должность** (A)
	ИИ оценивает насколько название вакансии совпадает с должностью из резюме пользователя

	**Система оценки**:
	- Полностью совпадает - 2 балла
	- Схоже по сути, но отличается по названию - 1 балл
	- Ни название, ни суть не совпадает - 0 баллов
	Множитель влияния на общую оценку - 0,05 (5%)

- **Задачи** (B)
	ИИ оценивает насколько задачи, которые будут возложены на кандидата на вакансии соотносятся с теми задачами, которые ранее брал на себя пользователь

	**Система оценки**:
	- Задачи из вакансии пользователь уже ранее на себя брал в таком же объёме или даже большем - 3 балла
	- Задачи из вакансии пользователь уже брал на себя, но в меньшем объёме, чем требуется в вакансии - 2 балла
	- Задачи из вакансии пользователь на себя не брал, но брал схожие/смежные по логике вакансии или его компетенций достаточно, что бы быстро обучиться новым задачам или вакансия подразумевает обучение - 1 балл
	- Задачи из вакансии пользователь на себя не брал ранее и их выполнение на приемлемом уровне будет требовать длительного обучения - 0 баллов
	Множитель влияния на общую оценку - 0,3 (30%)

- **Сфера** (C)
	ИИ оценивает насколько сфера (область деятельности) вакансии и компании совпадает сферами, в которыми ранее работал пользователь.

	**Система оценки**:
	- Сфера вакансии и компании совпадает с одной из тех, в которых ранее работал пользователь. Профиль задач в вакансии не отличается от тех, что брал на себя ранее пользователь (например, если пользователь работал с B2C продуктами, то и вакансия должна подразумевать работу с клиентами-физлицами, а не бизнес-клиентами) - 4 балла
	- Сфера вакансии и компании совпадает с одной из тех, в которых ранее работал пользователь. Профиль задач в вакансии отличается от тех, что брал на себя ранее пользователь (например, если пользователь работал с B2C продуктами, то и вакансия подразумевать работу с бизнес-клиентами, это снижает релевантность вакансии) - 3 балла
	- Сфера вакансии и компании имеет косвенные совпадения с одной из сфер, в которых пользователь ранее работал. Профиль задач в вакансии не отличается от тех, что брал на себя ранее пользователь (например, если пользователь работал с B2C продуктами, то и вакансия должна подразумевать работу с клиентами-физлицами, а не бизнес-клиентами) - 2 балла
	- Сфера вакансии и компании имеет косвенные совпадения с одной из сфер, в которых пользователь ранее работал. Профиль задач в вакансии отличается от тех, что брал на себя ранее пользователь (например, если пользователь работал с B2C продуктами, то и вакансия подразумевать работу с бизнес-клиентами, это снижает релевантность вакансии) - 1 балл
	- Сфера вакансии и компании не совпадают. Профиль задач в вакансии отличается от тех, что брал на себя ранее пользователь (например, если пользователь работал с B2C продуктами, то и вакансия подразумевать работу с бизнес-клиентами, это снижает релевантность вакансии) - 0 баллов

	Множитель влияния на общую оценку - 0,25 (25%)

- **Года опыта** (D)
	ИИ оценивает насколько требуемый в вакансии опыт в годах соответствует опыту пользователя в годах

	**Система оценки**:
	- Вакансия требует опыта меньше или столько же, сколько есть у пользователя - 2 балла
	- Минимальные требования по годам опыта отличается от лет опыта пользователя не больше чем на 1 год - 1 балл
	- Минимальные требования по годам опыта отличается от лет опыта пользователя больше чем на 1 год - 0 балл

	Множитель влияния на общую оценку - 0,20 (20%)

- **Требование к знанию языков** (E)
	ИИ оценивает требования вакансии к знанию иностранных языков

	**Система оценки**:
	- Вакансия не требует знание иностранных языков или уровень знания иностранного языка пользователя выше или равен тому, что требуется в вакансии - 2 балла
	- Вакансия требует знания иностранного языка незначительно выше (не выше чем на 1 уровень), чем владеет пользователь - 1 балл
	- Вакансия требует знания иностранного языка значительно выше (выше, чем на 1 уровень), чем владеет пользователь - 0 баллов
	Множитель влияния на общую оценку - 0,1 (10%)

- **Требование к навыкам** (F)
	ИИ оценивает насколько перечень навыков, которые работодатель перечисляет в поле "Ключевые навыки" совпадает с навыками, которые указал пользователь в резюме

	**Система оценки**:
	- Вакансия требует только те навыки, которые у пользователя указаны в резюме - 1 балл
	- Вакансия требует не более 2 навыков, которых нет у пользователя - 1 балл
	- Вакансия требует более 2 навыков, которых нет у пользователя, но они по логике схожи с теми, что у пользователя есть - 1 балл
	- Вакансия требует более 2 навыков, которых у пользователя есть и эти навыки не схожи с теми, что у пользователя есть - 0 баллов
	Множитель влияния на общую оценку - 0,1 (10%)

Итоговая формула для расчёта баллов: ((A/2) * 0,05 + (B/3) * 0,3 + (C/4) * 0,25 + (D/2) * 0,2 + (E/2) * 0,1 + (F/2) * 0,1) *100. Дробные значения округляются до единиц по правилам математики.

Баллы выставляются по 100 бальной шкале

Порог определяет, какие вакансии считать подходящими. Для HH.ru он также влияет на решение об отклике; для HireHi — только на отбор вакансий в PDF-отчёт. По умолчанию стоит 70 баллов.

Так же есть механизм отклонение вакансии даже при условии достижения проходного балла, если она не набрала минимальный балл по одному или нескольким критериям

## Первый запуск

1. На вкладке «Модель» укажите Base URL облачного OpenAI-compatible API, вставьте API-ключ, выберите доступную модель и сохраните изменения.
2. Заполните личный профиль вручную или импортируйте резюме из PDF, DOCX либо TXT.
3. Проверьте и отредактируйте импортированные поля, добавьте недостающие данные и выберите резюме для matching.
4. Естественным языком опишите, какие вакансии нужно искать, и задайте порог отбора от 0 до 100 баллов.
5. Запустите mock-сессию для проверки или сессию HH.ru либо HireHi. HH.ru ищет, оценивает и может отправлять отклики; HireHi только собирает подходящие вакансии в PDF и никогда не откликается. Для первого входа нажмите «Открыть браузер» и авторизуйтесь в отдельном профиле Chromium.

CAPTCHA, MFA, тестовые задания, неизвестные вопросы и чувствительные данные всегда требуют ручного решения. Реальную отправку на HH.ru следует подтверждать пользователю; автоматические тесты её не выполняют.

Ключ хранится зашифрованным Windows DPAPI для текущего пользователя. API и логи его не возвращают. Восстановить ключ из интерфейса нельзя; после смены пользователя Windows его потребуется ввести заново.
Публичный Base URL должен использовать HTTPS. HTTP разрешён только для уже настроенного локального loopback-gateway.

## HireHi

HireHi только собирает подходящие вакансии и формирует PDF-отчёт. Отклики не отправляются, формы не заполняются и контакты работодателей не сохраняются в отдельный список. В отчёт попадают тип маршрута вакансии (встроенный чат, прямой контакт или внешний работодатель), ссылка и найденные контактные данные — чтобы пользователь мог сам решить, что делать дальше.

## Параллельные сессии

Сессии на разных сайтах (например, HH.ru и HireHi) можно запускать одновременно. Каждая сессия имеет отдельную карточку, статус, счётчики, события и действия запуска/продолжения/остановки.

Внутри одного сайта одновременно допускается только одна незавершённая сессия: persistent-профиль Chromium общий для site-level авторизации и защищён lease-механизмом. Сессии, заранее созданные в статусе `CREATED`, друг друга не блокируют.

## Уведомления

Справа от надписи «API» в верхней части интерфейса находится колокольчик. Непрочитанные уведомления отмечаются красным кружком; нажатие на колокольчик открывает выпадающий список. При появлении уведомления воспроизводится звуковой сигнал, а нажатие на него переводит пользователя на вкладку источника. Уведомления универсальны по структуре, но сейчас создаются событиями сессий: при запуске и смене статуса (кроме перехода `WAITING_FOR_LOGIN` в `RUNNING`).

Backend API уведомлений:

- `GET /api/notifications` — список уведомлений;
- `PATCH /api/notifications/{id}/read` — пометить уведомление прочитанным;
- `POST /api/notifications/read-all` — пометить все уведомления прочитанными.

Новый адаптер регистрируется через factory registry и получает независимый runtime instance; при запуске ему автоматически назначается отдельный site lease.
